## 必须修复

### P0-1 流体替换不检查是否匹配，会替换所有流体
位置：`TinkerComponents` 中 `FluidIngredientComponent.replaceInput`、`FluidOutputComponent.replaceOutput`、`FLUID_OUTPUT_UNIT.replaceOutput`、`ORE_BYPRODUCT.replaceOutput`。

依据：KubeJS 的 `RecipeJS.replaceInput` 会对每个输入值都调用 `RecipeComponentValue.replaceInput`，是否匹配由组件自己判断。KubeJS 默认的 `RecipeComponent.replaceInput` 会先调用 `isInput`，这里的重写跳过了这一步。

后果：`event.replaceInput({}, Fluid.of('tconstruct:molten_iron'), Fluid.of('tconstruct:molten_gold'))` 会把所有匠魂配方里的流体都换成熔融金。

修复：先调用 `isInput` / `isOutput`，不匹配时返回原值。

### P0-2 替换时用量被改成替换物的用量
依据：KubeJS 自带的 `InputFluid.replaceInput` / `OutputFluid.replaceOutput` 会用 `kjs$copy(original.kjs$getAmount())` **保留原用量**。实施代码直接用了替换物的用量，`Fluid.of('x')` 默认是 1000 mB，所以 90 mB 的锭配方会变成 1000 mB。

修复：保留原值的用量，也就是 `FluidIngredient` 的用量、`FluidOutput.getAmount()`；`unit_size` 和 `rate` 也要保留。

### P0-3 物品原料和物品产物不能被匹配，相比不注册 Schema 是功能回归
位置：`INGREDIENT_REQUIRED/OPTIONAL`、`SIZED_INGREDIENT`、`ITEM_OUTPUT_*`、`ITEM`、`MATERIAL_ITEM`、`MODIFIABLE_ITEM`，这些都用 `LoadableComponent`，没有实现 `isInput/isOutput/replaceInput/replaceOutput`。

依据：不注册 Schema 时，KubeJS 用 `JsonRecipeJS` 处理这些配方。在 `matchJsonRecipes`（默认 true）开启时，它会通过 `getOriginalRecipe().getIngredients()/getResultItem()` 匹配物品。注册 Schema 之后，这条路径就不再走了。

后果：`event.remove({ output: 'minecraft:gold_ingot' })` 删不掉匠魂的浇铸配方，`event.remove({ input: 'minecraft:iron_ingot' })` 也删不掉熔化配方。

修复：
- 原料组件实现 `isInput`：`match instanceof ItemMatch m && m.contains(ingredient)`，写法参考 KubeJS 的 `ItemComponents.INPUT`；
- 产物组件实现 `isOutput`：把 `ItemOutput.get()` 转成 `ItemStack` 再调用 `m.contains`；
- 同时实现物品的替换，替换时保留数量。

### P0-4 标签流体的默认值会静默算错
位置：`TinkerRecipeJS.applyMeltingDefaults`、`applyCastingDefaults`、`applyTemperatureDefault`。

依据：配方事件期间，KubeJS 只给物品 Ingredient 打了标签补丁（`IngredientTagValueMixin` 使用 `TagContext.INSTANCE`）。Mantle 的 `FluidIngredient.getFluids()` 和 `FluidOutput.get()` 用的是注册表标签，首次加载世界时这个标签还没绑定，`/reload` 时拿到的则是旧数据。

后果：
- 熔化配方用标签作产物时，`result.get()` 为空，`getTemperature` 返回 0，于是**静默写出 `temperature: 0`**；
- 浇铸配方用标签流体时，`getFluids()` 为空，代码直接 return，`cooling_time` 缺失，匠魂加载时报错；
- 违反实施文档第 5 节"不允许静默填值"的规定。

修复：
- 标签用 `TagContext.INSTANCE.getValue().getTag(TagKey.create(Registries.FLUID, id))` 解析，取第一个流体来计算；
- 解析不到时抛出英文异常，要求显式填写数值；
- 只有具体流体 ID 才直接计算。

### P0-5 合金默认温度来源错误
依据：匠魂真实配方 `molten_bronze` 的温度是 700，等于产物 `molten_bronze` 的 FluidType 温度 1000 减去 300；输入的铜是 800 − 300 = 500，对不上。`AlloyRecipeBuilder.alloy(FluidObject, amount)` 也是按**产物**取温度。

修复：合金按 `result` 计算温度。

### P0-6 `TinkerRecipes.metal` 有多处错误
1. 温度默认写死成 `500`，违反第 5、6 节。应按流体计算，计算方式同 P0-4。
2. 配方 ID 重复了 `metal/` 前缀：`path` 本身已经带 `metal/`，`add()` 又加了一次，结果变成 `tinkers_kubejs_arsenal:metal/metal/<名>/...`。
3. 副产物被加到锭、块、粒的熔化上。匠魂只在矿石熔化上加副产物，参见 `smeltery/melting/metal/iron/ore_singular.json`。
4. 矿石熔化：匠魂的单矿是 **180 mB**（`rate: metal`），实施代码写的是 90 mB，`rate` 默认为 `default`。另外缺了 `raw_materials/<名>`（90 mB）、`storage_blocks/raw_<名>`（810 mB），以及稀疏矿、密集矿的区分。匠魂用 `tconstruct:non_singular_ore_rates` 和 `mantle:tag_combination_filled` 条件来处理，照它的数据文件实现。
5. 块浇铸用的铸模标签 `tconstruct:casts/multi_use/block` **不存在**（`tags/items/casts/multi_use/` 下没有 `block`），这个配方永远无法完成。匠魂的块浇铸不需要铸模，参见 `smeltery/casting/metal/iron/block.json`。
6. 没有一次性沙铸模的配方：需要 `tconstruct:casts/single_use/*`，并设 `cast_consumed: true`，参照 `ingot_sand_cast.json`。
7. 选项 `cast` 现在控制的是**整个浇铸配方**，而文档的本意是"是否生成铸模"。锭、粒、块的浇铸应该始终生成。
8. 重复检测只查了自己的 ID，查不到匠魂自带的配方，例如 `tconstruct:smeltery/melting/metal/<名>/ingot`、`tconstruct:smeltery/casting/metal/<名>/ingot_gold_cast`。按这些 ID 规律检测，存在时跳过对应条目。

## 应当修复

- **P1-1 补全类型**：`TinkerComponents` 里有 11 处 `TypeDescJS.ANY`，违反审核清单。按真实可接受的输入写类型描述，例如：
  - Ingredient 用 `ctx.javaType(InputItem.class)` 或 string；
  - ItemOutput 用 string 或 `{item, count}` / `{tag, count}`；
  - EntityIngredient 用 string 或 `{type}` / `{tag}`；
  - 只有 `MaterialPredicate` 这类结构太复杂的组件，可以保留 object。
- **P1-2 下限不一致**：浇铸类 `cooling_time` 用了 `NON_NEGATIVE_INT`，而匠魂的 `COOLING_TIME_FIELD` 要求 ≥1，应改为 `POSITIVE_INT`。
- **P1-3 缺 `melting_fuel` 校验**：`fluid` 非空且 `duration == 0` 时，Schema 层应先抛出英文异常，和匠魂 `MeltingFuel` 的 validate 一致。
- **P1-4 字符串流体的默认用量**：只写 `'tconstruct:molten_iron'` 时会静默变成 1000 mB。匠魂的配方里几乎都需要明确用量，建议没写用量时直接报错。

## 建议

- **P2-1 枚举解析方式不统一**：`ORE_BYPRODUCT` 手写了 `valueOf(toUpperCase())`，而顶层 `rate` 用的是 `EnumComponent`。统一改用 `TinkerLoadables.ORE_RATE_TYPE` 解析，避免两边不一致。
- **P2-2 缺交付说明**：本次没有附交付说明。实施文档要求说明提前注册了哪些第二、三期配方，以及哪些行为和文档不同。

## 修复后复审方式

1. 再跑 `verify_schema.py`，字段比对结果应保持不变。
2. 逐条核对 P0 修复点的代码。
3. 用户决定是否进游戏验证。游戏内至少要验证这几项：
   - 流体替换只影响匹配到的流体，并且保留用量；
   - `event.remove({output: 物品})` 能删掉浇铸配方；
   - 用标签流体写熔化配方时，温度正确，或者明确报错；
   - `metal()` 生成的配方 ID 和内容与匠魂原版一致。
